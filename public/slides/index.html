01. Diretriz do Projeto

Requisitos Arquiteturais Exigidos

"A arquitetura ideal se baseia na construção de uma aplicação moderna e 100% em nuvem, desenhada ponta a ponta para integrar interfaces ricas com inteligência artificial avançada. Frontend em PWA com Tailwind CSS e Vanilla JavaScript; autenticação Google via Firebase; distribuição por Firebase Hosting; motor lógico em API RESTful Python no PythonAnywhere implementando o Model Context Protocol (MCP); Cloud Firestore sustentando RAG Estruturado e RAG Não Estruturado; orquestrado pela raiz documental GEMINI.md e prompts estruturados em Markdown."
100% em Nuvem

Zero dependência de infraestrutura local para execução. Todos os componentes rodam em serviços serverless e distribuídos.

IA com Duplo RAG

Combinação de dados estruturados (coleções Firestore) com regras documentais (normas e regulamentos) para eliminar alucinações.

Raiz GEMINI.md

Documento mestre de engenharia que governa o código, garantindo reprodutibilidade e conformidade contínua.

03. Camada de Apresentação

Frontend: PWA, Tailwind CSS e Vanilla JS

Progressive Web App

  • • Manifesto manifest.json com ícones 192px/512px.
  • • Service Worker (sw.js) para cache de assets estáticos e suporte offline.
  • • Instalável diretamente no Android, iOS e Windows sem precisar de loja.

Tailwind CSS Modular

  • • Design moderno, minimalista e altamente responsivo.
  • • Sistema de tokens e utilitários consistentes para espaçamento, tipografia e cores.
  • • Ausência de CSS redundante ou frameworks pesados.

Vanilla JavaScript

  • • Módulos ES6 nativos (app.js e area-testes.js).
  • • Zero dependências externas de React ou Vue, garantindo peso mínimo e performance instantânea.
  • • Separação clara entre Interface, Estado e Chamadas de API.
04. Identidade & Distribuição

Firebase Authentication & Firebase Hosting

Firebase Auth (Google OAuth)

A porta de entrada segura da aplicação:

  • Autenticação = IDENTIDADE: Validação oficial via Google Provider sem necessidade de armazenar senhas em banco.
  • Captura de Dados do Perfil: Coleta nome, foto oficial e e-mail para personalizar imediatamente o painel do usuário.
  • Blindagem do Assistente de IA: O widget de chat inteligente só é renderizado para usuários com sessão ativa.

Firebase Hosting (Distribuição Global)

Entrega estática de alto desempenho em nível mundial:

  • Edge CDN Global & SSL Automático: Carregamento ultrarrápido com compressão Gzip e cache inteligente.
  • URL Oficial em Produção: Disponível para qualquer usuário em https://projetosteste-e7490.web.app/.
  • Deploy Automatizado: Script de release direta (deploy_hosting.js) via Google Cloud API.
05. Motor Lógico

Onde Está o Backend? Python no PythonAnywhere

Tecnologia & Hospedagem

API RESTful em Python (app_pythonanywhere.py)

O backend não roda em servidor local; está hospedado na nuvem do PythonAnywhere, operando sob WSGI:

  • • Linguagem: Python 3.10+ com microframework Flask e Flask-CORS.
  • • Segurança de Credenciais: Acesso autenticado ao Cloud Firestore via Firebase Admin SDK e chave privada de Service Account protegida.
  • • Isolamento: Segredos e chaves de API nunca ficam expostos no código do cliente.
Responsabilidades Centrais

A Ponte Entre Frontend e IA

1. Intermediação Segura: Recebe a consulta do frontend, valida a sessão e recupera os dados de contexto.
2. Orquestração do Duplo RAG: Consulta o Firestore em busca de registros e injeta o regulamento não estruturado.
3. Tratamento de Quota e Resiliência: Trata graciosamente erros de rate limit (HTTP 429) informando o usuário sem quebrar o app.
06. Ferramentas da IA

Model Context Protocol (MCP) no Backend

GET /api/mcp/tools

Servidor de Ferramentas Estruturadas

Conforme exigido na arquitetura, a API Python atua como um servidor MCP que expõe ferramentas sistêmicas para que o modelo de linguagem possa consultar dados e tomar ações reais com parâmetros validados:

consultar_catalogo_servicos

Recupera serviços avulsos cadastrados com filtro por categoria.

args: categoria (string)
consultar_ranking_prestadores

Consulta os melhores prestadores por nota, especialidade e cidade.

args: categoria, cidade, limite
consultar_solicitacoes_abertas

Lista demandas em aberto no mural disponíveis para elaboração de propostas.

args: categoria, status
07. Coração dos Dados

Cloud Firestore: Papel Duplo & RAG

1

RAG Estruturado (Dados Vivos)

O Firestore é a Fonte Única da Verdade dos dados persistentes:

  • • Coleção usuarios: Perfis, reputação e dados cadastrais.
  • • Coleção servicos: Catálogo de preços-base e prazos médios.
  • • Coleção solicitacoes: Demandas de clientes com status de ciclo de vida.
  • • Coleção orcamentos: Decomposição de mão de obra e insumos.
2

RAG Não Estruturado (Regras & Normas)

O Firestore e a base documental fornecem contexto normativo e semântico:

  • • Políticas oficiais de sigilo concorrencial de orçamentos.
  • • Diretrizes de proteção de dados e chave Pix.
  • • Regras de garantia legal do Código de Defesa do Consumidor (CDC).
  • • Fórmula matemática oficial de pontuação do ranking.
Firestore Security Rules: Princípio de "negar por padrão", garantindo que nenhum usuário leia orçamentos concorrentes ou dados de terceiros sem autorização expressa.
08. Governança do Projeto

O Papel do Arquivo GEMINI.md na Raiz

O Guia Diretor Universal

O GEMINI.md é a espinha dorsal de engenharia:

  • • Define COMO a aplicação deve ser arquitetada (princípios, restrições e padrões de nuvem).
  • • Impede a IA e os desenvolvedores de inventarem tecnologias desconexas ou substituírem o stack sem autorização.
  • • Garante a reprodutibilidade e consistência do projeto entre diferentes máquinas e sessões.

A Regra Fundamental de Separação

GEMINI.md = COMO arquitetar (Nuvem, PWA, RAG, MCP, Segurança)
PROJETO.md = O QUE a aplicação faz (Marketplace de Serviços, Orçamentos)

Essa separação garante que a arquitetura universal possa ser reutilizada em qualquer outro produto no futuro.

09. Engenharia de Prompts

Prompts Estruturados Puramente em Markdown

Por Que Markdown Puro?

LLMs modernos (como o Gemini) foram pré-treinados com bilhões de tokens formatados em Markdown. A estrutura por títulos, seções e tabelas maximiza a atenção posicional do modelo.

Elimina ambiguidade entre instrução e dados.
Formato padronizado e versionável no Git.
Saída rica com tabelas e formatação para o usuário.

10. Aplicação Concreta

Regras de Negócio do ServiçosApp

Solicitante NÃO é Prestador

Quem contrata não vende serviços e não emite orçamentos para outros. Apenas o perfil cadastrado como "Ambos" dispõe do alternador rápido para navegar nos dois ambientes.

Orçamentos Discriminados

Todo orçamento emitido segrega: Mão de Obra Técnica + Tabela de Materiais/Peças + Taxa de Deslocamento + Prazo de Execução + Garantia Técnica (90 a 365 dias).

Sigilo & Proteção Pix

Prestadores concorrentes não veem valores alheios. Chaves Pix nunca são abertas ao público; a fatura com QR Code dinâmico é liberada apenas após o aceite formal do cliente.

11. Engenharia de UX/UI

Usabilidade e Experiência do Usuário

Sistema de Notificações Toasts

Substituição completa do alert() nativo do navegador por notificações animadas no canto superior direito:

  • • Não bloqueia a interface do usuário.
  • • Cores semânticas (Verde = Sucesso, Azul = Info, Vermelho = Erro).
  • • Auto-fechamento com transição CSS suave (toastSlideIn/Out).

Rolagem Elegante (.menu-scrollbar)

Solução definitiva para evitar que títulos de abas e botões fiquem escondidos:

  • • Barra de rolagem sutil e moderna (5px) com cantos arredondados, visível quando necessário.
  • • Botões de navegação lateral com setas (< e >) para rolar abas suavemente em desktops.
  • • Proteção de quebra de texto com whitespace-nowrap.

13. Honestidade Acadêmica

Desafios, Limitações & Pontos a Evoluir

Cota da API Gratuita

O tier free do Gemini possui teto de 5 requisições por minuto (RPM).

Mitigação Atual: Captura de HTTP 429 informando o usuário para aguardar 30s.

Custódia Financeira (Escrow)

O Pix é direto entre as partes. Em marketplaces consolidados, o valor deve ficar retido na plataforma.

Evolução Futura: Gateway de split payment com retenção e liberação por etapa.

Banco Vetorial Dedicado

O RAG Não Estruturado atual é injetado via prompt, limitado pela janela de contexto do LLM.

Evolução Futura: Integrar ChromaDB ou Pinecone para documentos volumosos.

A arquitetura atendeu rigorosamente todos os critérios de modernidade em nuvem, separação de responsabilidades, inteligência artificial contextual e governança técnica do projeto.
